# 03｜探索与决策

[English](03-exploration-and-decision.md) | 简体中文

在充分了解现状、掌握相关知识后，主动选择有价值的问题，组织研究与实现，并持续推进到目标负载下的实际效果。

## 选择值得深入的问题

先了解相关研究与上游实现、当前运行表现、历史实验的结果和取舍，读懂涉及的模型原理、执行机制与硬件特性。结合任务目标，判断哪些问题仍值得研究：

- 哪些开销影响主要负载，解决后可能带来明显改善？
- 已有方案解决了什么，又留下了哪些限制？
- 哪些不同思路值得比较，需要补充什么知识或实验？
- 调查、实现与验证需要哪些资源，如何安排才能持续推进？

按问题的重要性和潜在收益选择方向，不要因工作量大或实现困难，就只做浅层调参和容易完成的改动。对有价值的算法、算子或架构创新，投入必要的研究与实现；用工作量安排阶段和协作。

## 把发现变成研究任务

主 Agent、Advisor 和 Worker 主动从资料、源码和测量中提出具体问题。主 Agent 构思和调整方向、拆解任务、综合决策，统一负责环境准备、部署与并行实验。Advisor 提供独立研究、替代方案和反例。Worker 研究、寻找瓶颈、设计实现改动，分析主 Agent 返回的结果，无需等待 Advisor 交方案。

每项研究说明目前知道什么、想改变什么、下一步怎样获得有用结果。没有现成开关、脚本或 tuner 时，根据问题复用上游能力或构造局部实验，继续进入具体实现。

## 随结果持续深入

选定方向后，给源码分析、实验和实现留出连续投入。每轮改进生效后，重新测量并分析系统，找出新瓶颈和仍可改变的设计，接着提出下一轮问题。已经深入过的部分也要随新结果重新审视，在任务目标和预算内持续挖掘。阶段结果用于修正认识和完善方案：

- 出现收益：解释为什么有效、适用什么条件，继续处理剩余开销。
- 结果不明显：确认实现实际生效，检查预期改善与新增成本，再调整设计。
- 局部加速而服务收益有限：追踪集成后的执行，研究批处理、调度、数据放置与其他阶段的影响。
- 参数结果反复接近：重新检查共同的执行方式，探索不同的算法、并行维度或工作组织。

较大的改动可以拆成关键假设、核心实现和完整集成。先处理最影响可行性的技术问题，再完成真实请求下的执行。

## 保持研究主线

承接历史保留方案和可比结果，复测围绕版本、负载或实现发生的具体变化。短实验先回答当前问题，收益不确定、尾延迟或稳定性需要进一步判断时，再扩大测量。

构建、下载、部署、评测和结果记录优先复用 Foretoken 已有入口、缓存与产物，包括[源码增量更新](../../../docs/custom-deployment_zh.md)。先了解框架提供的能力和用法，确实无法满足当前实验时，再补充必要的临时脚本或工具。等待结果期间推进源码阅读、设计或其他独立工作，结果返回后及时分析并继续实验。

在完成一组实验、反复得到相近结果或准备总结时，重新检查重要热点是否已经解释，研究是否仍停留在相同的执行方式，以及哪些更深入的方案值得尝试。可以让另一个 Agent 阅读代码与证据，提出遗漏、反例和新的设计思路，再由主 Agent 综合判断。

## 并行探索与交流

按完整研究问题安排 Worker，让独立方向同时推进。给出目标、已有发现、范围和交付位置，并保留独立思考空间。Worker 持续研究、设计、修改并分析返回结果，与 Advisor 直接讨论机制，与 Recorder 核对证据。至少有一个 Worker 跟进整体执行路径，把局部发现与系统表现联系起来。

主 Agent 安装一次共享平台，再按[并行候选示例](../../../docs/custom-deployment_zh.md#并行运行候选方案)准备独立 worktree 和 Kubernetes namespace。Worker 修改分配的候选，交付工作区、改动与解释。主 Agent 从交付版的对应工作区同步并执行，修改引擎时用 `--engine-source` 关联候选引擎源码，复用源码增量更新和编译缓存。各候选保留独立的可写运行缓存与结果目录，条件允许时共享只读模型数据。共享控制器、CRD 或平台配置也由主 Agent 更新。

主 Agent 按实际容量安排并行构建、部署和测量，区分候选收益与共享 CPU、存储或网络争用的影响。候选运行时保持源码不变；Worker 继续独立研究、在另一 worktree 开发，或等主 Agent 释放工作区后恢复修改。主 Agent 及时返回结果，供 Worker 分析并继续开发。Worker 数量不必与 GPU 实验组数相同。

及时交换可复用实现、已排除的假设、新限制和可组合的改动。主 Agent 综合发现并选择保留改动，Worker 完成分配的代码整合，主 Agent 验证组合服务并验收结果。Advisor 持续探索与反思，Recorder 独立审查和记录证据。交付不意味着协作结束：继续推进范围内的工作，需要新任务时向主 Agent 提交结论与未解问题。
