# Foretoken 代码风格

[English](code-style.md) | 简体中文

提交流程见[贡献指南](../../CONTRIBUTING_zh.md)，验证命令见[测试规范](testing_zh.md#运行相关检查)。本文规定格式化工具无法判断的设计和维护标准。

这些标准适用于一方代码和发布制品。第三方与上游管理的源码遵循各自约定，Foretoken 适配层遵循本文。新增的一方源码、配置和脚本须使用仓库 SPDX 声明。机械格式与生成规则以 Makefile、Cargo 和 Go 工具、包配置及 pre-commit hooks 为准。修改权威来源后重新生成，不单独维护派生结果；生成产物须有可识别或已记录的来源。

## 按职责归属设计

修改局部前，追踪配置、执行、观测、决策和清理的完整路径。生产方与使用方保持一致的身份、状态作用域和生命周期归属，扩展副本、分片或节点时也须一起调整。在行为和失败语义完整的前提下，选择最小可维护实现。

协议值、默认值、状态转换和派生计算各有一个权威定义，使用方通过类型化契约或共享函数读取。资源生命周期的创建、使用、清理和发布由一个负责方承担，除非 API 明确移交。共同执行路径应复用，不在运行器、控制器或适配层中复制完整流程；调用者只保留不同输入和策略。

类型、辅助函数、配置字段、检查、回退和测试都须有当前职责，使用方消失时一并删除。新增抽象前，先删除重复路径、复用已有负责方、调用成熟上游的公共 API 和完整执行路径。trait、interface、factory、builder、registry 须对应真实职责边界或多个现有实现。

版本敏感和特定后端行为留在薄适配层。平台 API 与通用控制流使用与推理引擎无关的领域类型，不为未支持的版本或后端预建能力探测、回退实现或插件框架。

## 有意设计公共接口

CLI 参数、YAML、环境变量、CRD 和 API 字段、状态及持久化输出结构须对应当前用户选择和实际执行方。显式映射公共字段，不通过反射暴露整个 struct 或 dataclass，参数扫描也遵循此要求。

从模型标识、Kubernetes 资源等权威输入推导已有信息。内部修订、临时路径、控制器状态、运行时身份、中间结果和编排上下文不作为普通用户配置。

默认值只在负责的配置或生命周期边界定义一次。解码器和下游不能用空字符串、集合、零值或静默回退替代必需状态，应在负责边界报错；只有缺失是合法领域状态时才表示为空。

实验能力默认关闭并明确启用方式。稳定契约不能静默破坏，不兼容改动须有明确版本、弃用周期和迁移路径。

YAML 常用路径应简短，减少必填字段并使用准确领域名称，避免宽泛的 `target`、`policy`、`owner`、`extra` 或 `config`。高级选项归入职责明确的嵌套块，不用两个字段或文件表达同一决定。Helm values、schema、维护中的示例和文档保持同步；示例展示最小有用配置，不展开所有选项。

## 在负责边界暴露真实失败

默认不新增校验、固定限制、重试、回退、哈希、基线或流程门禁。优先使用直接实现、明确归属、类型、版本、主键、事务、唯一约束和普通测试。防御机制须保护当前可达的重要失败，且更简单的方式不足以解决。明确触发输入或状态、资源或契约的负责方、判定信号与用户可见结果，以及简单机制或上游校验为何不足。

只在负责边界校验一次，不在下游重复。必需状态缺失和协议失败保持可见，不转成空结果或默认值。只捕获调用者能处理的错误；宽泛异常处理不能把编程错误、SDK 误用或不变量破坏伪装成远端失败。

## 按职责组织代码

使用 `create_client`、`metrics_url`、`model_group` 等具体领域名称。值保留在负责它的最小作用域；模块常量须有多个使用方或表达模块级外部契约，不只为书写方便。

相关阶段保持一条可读流程。提取函数须对应有意义的阶段或生命周期，不用零碎转发函数缩短代码。多个阶段持续持有资源、client、配置或不变量时，Python 使用有状态 class，Go 和 Rust 使用带方法的 struct。无状态转换和单阶段操作继续使用函数；不为命名空间、缩短参数或假设复用建立类型。

有状态模块集中其生命周期和相关类型。当前实现共享的行为放在基类，适配层识别、容量和策略留作特化方法，使一个适配层可以完整阅读。只将可复用的无状态解析、匹配和格式化移到具名辅助模块。共同承担生命周期的多个 class 可放在同一文件，不机械要求一文件一类。

按独立生命周期、协议、后端或归属边界拆模块，不按长度拆分；内聚长文件可以保留。

入口只组合和分发，不决定领域策略。多个现有模块共享稳定职责时建立领域 package，不为未来实现创建空层级、通用 `utils` 层、registry 或目录。

功能明显增长后重新检查职责图，删除旧路径、重复状态与阶段、转发层，确认拆分减少维护者需要理解的概念和实现总量。

一方生产代码的公开函数须有简短文档注释，说明用途、调用或使用方、返回或发布结果，以及重要归属或生命周期。承担完整阶段，或无法从名称和签名理解的私有函数也需这些说明。生成和第三方代码遵循所属项目。

大块代码、多阶段流程、非直观算法和关键边界使用少量结构注释，说明必要顺序、资源归属、外部约束、失败或清理后的状态，不复述 getter、字段透传、常量映射、明显循环或每行代码。注释不记录修改历史、评审回复、临时计划或实现者推理过程。

## 遵循所属语言和工具

沿用相邻代码和子目录可执行检查。Python CLI 参数定义与解析同执行分离，跨边界传递明确命令类型，不传 `argparse.Namespace`。评测沿用已有包结构和类型风格。Helm 和 Kubernetes 的资源、schema、选择器、端口、命名空间和网络访问作为一条部署契约验证。

[测试规范](testing_zh.md)负责特征选择、真实执行、不使用 mock、位置和测试审查；[CI 规范](ci_zh.md)负责调度、产物验证、权限、清理和合并检查。两者都复用产品生命周期，并有当前负责方，不维护重复实现或推测性检查。

## 围绕读者任务编写文档

新增或大幅重写用户文档前，明确页面用途与读者结果，核对当前代码、CLI 帮助、values、schema、维护中的示例、运行和清理。

阅读至少两个职责相近成熟项目的最新指南。比较前提、首次成功、替代方案、验证和排障，借鉴组织而不复制文字。历史、弃用、草案和提案资料只作背景，不作为当前操作指南。先排最短可执行路径，再写说明。

每页承担一项职责。根 README 介绍项目并提供从准备、成功请求到清理的默认路径。组件 README 说明用户可见的用途、输入、输出、访问和必要限制，不写源码导览或私有契约。安装、部署、运维、排障和参考指南各自负责细节。维护者指南可说明归属、数据流与取舍，但区分当前行为、目标和草案。

命令使用维护中的路径、模型标识、字段和默认值。无法避免的占位符在使用前解释，修改配置时展示准确片段。

只有依次执行才将命令放在一起，并简短标注不同阶段；不在概览重复命令，也不复述明显操作。

说明可观察结果、资源和成功标准，等待与内部生命周期仅在影响下一步时出现。替代方案放在实际选择点，或链接所属指南，不在开头枚举所有模式。

能力增长时调整读者路径，不机械追加段落。共同行为写一次，差异放入聚焦章节，示例与贡献者等增长列表使用稳定入口。面向未来使用者和维护者，不记录 PR 讨论或实现日记。

以首次使用者、熟练运维者和源码开发者的视角通读完整路径。发现具体阻力时先调整页面职责、结构和位置，再改句子，并重读相邻步骤。

独立删除重复命令、介绍文档组织的元叙述、错位选项、无用实现细节及没有用途的标题。默认路径可执行、选择适时出现且读者无可达阻塞时停止纯措辞迭代；格式和测试不能替代阅读。

中英文的能力、前提、命令、默认值和限制一致，但各自自然成文，不逐句翻译。读者需要识别或输入的命令、字段、类型和 Kubernetes 资源名保持原样，不常见术语首次使用时解释。

## 审查最终差异

每个 PR 聚焦一项职责，不混入无关重构、升级、格式化或生成漂移。删除替代掉的实现、无用配置、重复默认值、旧文档和只保护旧路径的测试。确认基线，说明堆叠 PR 的前置 PR，不重新引入 `main` 已替代的行为。

先检查正确性和完整执行路径，再独立检查简洁性、归属和维护成本。隐私、来源和如实报告验证遵循[贡献指南](../../CONTRIBUTING_zh.md#保护私有信息并核对来源)。使用 [PR 模板](../../.github/PULL_REQUEST_TEMPLATE_zh.md)概述问题、改动、证据、性能、影响和关联 Issue，不在 PR 中复制这些标准。
