# 源码更新生命周期

[English](source-image-lifecycle.md) | 简体中文

安装和更新命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。维护更新流程时需保持以下约束。

## 构建与发布

平台安装负责共享控制器、CRD 和默认运行环境。源码部署选择当前目录所在的 Foretoken Git 源码树，或通过 `-e PATH` 明确指定，只构建前端和模型服务的运行环境及应用，不重新安装平台，也不发布候选中的控制面改动。

每个源码树独立拥有源码状态、构建绑定、编译缓存及记忆的引擎目录。同一源码树的构建和服务提交串行执行，不同源码树可以并行构建和部署。等待就绪时不占用源码操作锁，已完成的候选可以删除并释放资源。新 worktree 不继承其他 worktree 的引擎目录。即使候选共用镜像仓库或平台应用存储，构建工作目录、构建守护进程存储和导出目录仍保持独立。

同步包含文件删除；引擎更新不能从运行时镜像恢复已删除的源码。编译缓存与模型数据分开，构建结果须兼容所选运行时的 Python 和设备库。

完整应用版本发布后才能使用，发布后保持不变。再次使用编译输出前，先停止该构建遗留的发布进程。平台独立管理应用存储，不与编译缓存或模型缓存混用。

## 选择与恢复

源码发布在可信应用源的不可变清单中同时记录环境镜像和文件。服务选择发布版本，不直接指定任意镜像或下载地址。控制器解析并保存该选择后，再创建工作负载；已有选择不依赖再次读取清单。模型准备与推理使用同一版本，重启和扩缩容沿用该版本。平台安装更新默认值，不替换已有服务的选择。

选定版本和服务路由就绪后才能报告部署成功。滚动更新和请求排空由已有控制器负责。namespace 隔离候选服务与路由；GPU 请求和节点选择沿用 Kubernetes 调度器与设备插件。

## 清理

保留服务、工作负载模板、运行中或正在终止的工作负载、已保存任务及 Helm 回滚历史引用的版本。只删除发布者自身不再被引用的版本，保留其他发布者的在途工作。

删除候选只删除其部署，不卸载共享平台。Helm 管理应用存储。源码卸载删除托管编译缓存和工作站绑定，保留模型数据。
