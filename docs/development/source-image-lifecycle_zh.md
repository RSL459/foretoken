# 源码部署生命周期

[English](source-image-lifecycle.md) | 简体中文

安装、部署和并行候选的命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。本页说明维护该流程时需保持的职责边界。

## 安装与部署

平台安装负责共享控制器、CRD 和默认运行环境。部署从选定的代码目录构建前端及模型服务，只应用到本次提交的服务。两者分开，才能避免一个候选改变其他候选使用的平台。

CLI 按代码目录记录引擎目录选择，并在准备构建时同步源码删除。已删除的引擎文件不能从基础镜像重新出现。构建结果需兼容选定的 Python 和设备库。

## 并行构建

同一代码目录的源码准备和服务提交串行执行，其他目录可同时构建；平台安装、卸载与这些操作互斥。等待服务就绪前释放源码操作锁，使删除操作能够为尚未调度的服务腾出设备。

编译缓存用于复用构建输入，不承担运行服务的状态。访问由构建器协调，候选之间不能覆盖彼此的可写源码及导出目录。复用输出前，先停止可能仍在读写这些文件的遗留发布任务。

## 运行与清理

环境镜像和完整应用文件通过可信应用源的不可变清单一起发布。控制器先解析并保存选择，再创建工作负载，使模型准备、推理、重启和扩缩容始终使用同一份代码，而不依赖重新读取清单。部署成功要求选定代码和服务路由均已就绪；滚动更新与请求排空仍由控制器负责。

应用存储归平台管理。清理时保留服务、工作负载、已保存任务或 Helm 回滚历史引用的发布，只删除发布者自身不再使用的文件。删除候选只删除其部署，不卸载共享平台。卸载释放托管构建资源和本地源码记录，保留模型数据。
