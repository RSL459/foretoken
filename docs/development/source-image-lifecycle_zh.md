# 运行时源码生命周期

[English](source-image-lifecycle.md) | 简体中文

源码更新将应用代码与运行环境依赖分开管理。安装和更新命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。

## 准备与发布

CLI 管理工作站上的源码绑定、安装设置和输入快照。同一工作站对同一集群的源码操作串行执行，先同步文件变化和删除信息，再开始构建。

BuildKit Pod 使用持久编译缓存，与模型存储分开。每个组件针对所选运行环境准备一次，不按模型命名空间重复编译。再次使用编译输出前，先停止同一绑定遗留的发布 Job。

应用文件发布到平台管理的 HTTP 文件服务和存储卷。发布 Job 与文件服务位于同一节点，因此 ReadWriteOnce 存储也能供其他节点上的工作负载读取；BuildKit Pod 不挂载发布卷。发布以原子方式完成后，工作负载才能选择该版本，已发布文件保持不变。

## 引擎源码与编译扩展

显式关联的引擎源码与仓库固定的 vLLM Rust 依赖相互独立。Python 模块来自关联源码，并应用 Foretoken 补丁；兼容动态库和生成的依赖文件由运行时提供。已删除的源文件不能从镜像中的旧包重新出现。

原生扩展使用所选运行时的 Python、PyTorch 和设备库，复用上游增量缓存。沐曦原生扩展更新使用编译后的插件，而非预编译 kernel 包。更新依赖时需保持与这些设备库兼容。

## 工作负载生效

CLI 在服务上选择源码版本，控制器负责前端滚动更新和模型 Pool/Group 替换。模型准备与所有推理成员，包括 LWS 的 leader 和 worker，使用同一文件选择。下载初始化容器将应用文件准备到 Pod 本地存储，不依赖 RuntimeCache 或共享模型卷。

工作负载直接启动下载的程序，并使用对应的 Python 和引擎路径。应用文件只读，模型数据、运行期缓存和性能采集输出使用独立的可写存储。

源码更新时，Helm 选择控制面文件，在执行 CRD 引导程序和 manager 前完成下载。已保存的视频任务计划保留执行和清理所需的应用版本。CLI 核对实际运行的镜像、源码、完整推理副本、路由状态和 Service 端点后报告成功；控制器负责路由撤回和请求排空。

## 环境更新与清理

运行环境依赖、镜像构建配置或 Helm 配置变化时，使用平台安装流程。完整源码安装成功后清除服务的源码选择和控制面的文件选择，使工作负载使用新镜像。

清理时保留服务意图、Pool/Group 模板、准备 Job、运行中或正在终止的工作负载、视频任务计划以及 Helm 回滚历史所引用的版本。发布者只删除自己绑定不再使用的版本，保留其他发布者的在途文件。

Helm 管理文件服务和发布卷。源码卸载会删除托管编译缓存和工作站绑定，保留模型数据。vLLM-Omni 使用独立的[镜像构建配方](../custom-deployment_zh.md#vllm-omni-运行时)。
