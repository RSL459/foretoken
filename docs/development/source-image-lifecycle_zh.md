# 运行时源码生命周期

[English](source-image-lifecycle.md) | 简体中文

源码更新将应用代码与运行环境依赖分开管理。安装和更新命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。

## 准备与发布

CLI 在工作站保存源码绑定和安装设置。同一工作站对同一集群的源码操作串行执行，先同步文件变化和删除信息，再开始构建。

BuildKit Pod 使用持久编译缓存，与模型存储分开。应用文件发布到平台管理的 HTTP 文件服务和存储卷。发布 Job 与文件服务位于同一节点，因此 ReadWriteOnce 存储也能供其他节点上的工作负载读取；BuildKit Pod 不挂载发布卷。

发布以原子方式完成后，工作负载才能选择该版本，已发布文件保持不变。再次使用编译输出前，源码操作会先停止同一绑定遗留的发布 Job。

## 引擎源码与编译扩展

显式关联的引擎源码与仓库固定的 vLLM Rust 依赖相互独立。Python 模块来自关联源码，并应用 Foretoken 的引擎补丁；兼容动态库和生成的依赖文件由所选运行环境提供。已删除的源文件不能从镜像中的旧包重新出现。

原生扩展针对所选运行环境的 Python、PyTorch 和设备库构建，复用上游构建工具的增量缓存。沐曦使用实际编译的插件，而非预编译 kernel 包。更新依赖时，需保持与这些设备库兼容。

## 工作负载生效

控制器在创建工作负载前，将选定的运行时镜像和应用版本记入服务状态。重建、扩缩容和缩零后恢复均沿用这一选择，模型准备和所有推理成员使用同一版本。

下载初始化容器将应用文件准备到 Pod 本地存储。工作负载直接启动下载的程序，并使用对应的 Python 和引擎路径。应用文件只读，模型数据、运行期缓存和性能采集输出使用独立的可写存储。

Helm 管理控制面更新，应用文件和 CRD 在启动前准备好。CLI 确认选定版本、服务副本、路由和 Service 端点就绪后报告部署成功；替换过程中的请求排空仍由控制器负责。

## 环境更新与清理

运行环境依赖、镜像构建配置或 Helm 配置变化时，使用平台安装流程。平台更新改变新服务的默认设置，已有服务通过重新部署采用当前运行环境和应用文件。纯镜像服务在重新部署前保持原运行方式。

清理时保留服务选择、工作负载模板、保存的任务计划、运行中或正在终止的工作负载以及 Helm 回滚历史所引用的版本。发布者只删除自己不再被引用的版本，保留其他发布者的在途文件。

Helm 管理文件服务和发布卷。源码卸载会删除托管编译缓存和工作站绑定，保留模型数据。vLLM-Omni 使用独立的[镜像构建配方](../custom-deployment_zh.md#vllm-omni-运行时)。
