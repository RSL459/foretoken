# 运行时源码生命周期

[English](source-image-lifecycle.md) | 简体中文

源码更新将应用代码与提供依赖的镜像分开管理。安装和重新部署命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。

## 准备与发布

CLI 负责工作站上的源码绑定、安装设置与输入比较。绑定对应实际集群和已安装平台，不在工作站之间共享。同一工作站的源码操作按集群串行执行，先将新增、修改的文件和删除信息同步到集群工作区，再开始编译。

专用 BuildKit Pod 使用独立编译卷，不占用模型存储。Dockerfile 的导出阶段生成应用程序，Python 适配代码与关联的引擎源码组成完整代码包。Go、Cargo 和原生构建工具管理各自的增量缓存。同一运行环境的组件只准备一次，不按模型命名空间重复编译。

平台拥有独立的发布卷和 HTTP 文件服务。短生命周期的发布 Job 与文件服务同节点运行，只读挂载编译输出，因此 RWO 存储也能供其他节点消费。长驻 BuildKit Pod 不挂发布卷。Job 通过临时目录和重命名完成发布，复用上一版本未变化的文件，并在工作负载切换前结束。其期限和完成后保留时间沿用调用方的 timeout。下一次源码操作会先停止本绑定遗留的 Job，再复用编译输出。

已发布目录保持不变。回收保留当前代码选择、Service 意图、Pool/Group 模板、准备 Job、运行中或正在终止的消费者、Helm 回滚历史和 VideoTask 计划，只删除当前绑定不再被引用的版本，不回收其他发布者的在途文件。

## 引擎源码与编译扩展

显式关联的引擎源码与仓库固定的 vLLM Rust 依赖相互独立。Python 模块以关联源码为准；源码中没有的兼容动态库、生成文件和外部依赖文件由所选运行时补齐，同时保留 Foretoken 的引擎补丁。删除的源文件不能通过镜像中的旧 Python 包重新出现。

原生扩展使用所选运行时的 Python、PyTorch 和设备环境编译，在独立构建阶段补齐工具，并复用上游构建工具的增量缓存。沐曦更新选择实际编译的插件，而非预编译 kernel 包。运行环境变化时使用正常的包解析器，并保持所选设备 ABI 依赖一致。

## 工作负载生效

CLI 在服务上选择源码版本，控制器负责前端更新、ModelPool/ModelGroup 替换，以及一致的模型准备与推理配置。下载初始化容器将所选应用准备到 Pod 本地存储；代码运行不依赖 RuntimeCache 或共享模型卷。LWS 的 leader 和 worker 使用同一文件选择。

工作负载直接启动下载的程序。程序只激活对应 Python 和引擎路径，不再从旧镜像中选择另一个可执行文件。应用目录只读，模型数据、运行期编译和性能采集继续使用各自的可写存储。模型准备读取所选 Python 文件，不维护另一份嵌入程序的脚本。

控制面同样先下载程序和 CRD，再执行引导与启动。Helm 管理控制面的版本选择与更新；video-worker 计划保留后续执行和清理所需的文件版本。

CLI 在报告成功前核对实际运行的镜像与源码、完整服务副本集合、已消费的路由版本和 Service 端点。平台镜像变化不会推进 Service generation，旧的 Ready 状态不能单独证明所选版本已经运行。撤回路由、排空请求和释放资源仍由现有控制器负责。

## 环境更新与清理

运行时依赖、镜像构建配置或 Helm 配置变化时，使用平台安装流程。镜像仓库模式直接从集群推送产物；本地 kind/k3d 将镜像载入节点 containerd，不经客户端中转。镜像复用比较实际构建结果与已安装引用。

首次源码安装和环境更新都先准备只提供依赖的镜像，再发布完整应用文件，最后启动控制器。ModelService 的 status 保留各 Pool 的应用选择，供 Pool 重建恢复；ModelPool 和 ModelGroup 各自保存实际执行的环境镜像与应用 URL。重建、扩缩容及缩零后恢复均沿用原选择。前端在控制器拥有的 status 中保留同样的选择。平台更新只改变新服务的初值；已有服务由显式 deploy 选择当前应用。已有纯镜像副本在重新选择前保持纯镜像运行。平台文件服务跟随 Helm release。源码卸载会删除托管编译缓存和工作站绑定，保留模型数据。vLLM-Omni 仍使用独立的[镜像构建配方](../custom-deployment_zh.md#vllm-omni-运行时)。
