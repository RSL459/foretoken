# 运行时源码生命周期

[English](source-image-lifecycle.md) | 简体中文

源码更新将应用代码与运行环境依赖分开管理。安装和更新命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。

## 准备与发布

CLI 管理工作站上的源码绑定、安装设置和输入快照。同一工作站对同一集群的源码操作串行执行，先同步文件变化和删除信息，再开始构建。

BuildKit Pod 使用持久编译缓存，与模型存储分开。安装中断后保留缓存；再次使用编译输出前，先停止同一绑定遗留的发布 Job。临时镜像仓库 Secret 归构建 Pod 所有。

控制面程序和 CRD 发布到平台管理的 HTTP 文件服务和存储卷。发布 Job 与文件服务位于同一节点，在更新工作负载前释放挂载；BuildKit Pod 不挂载发布卷。完整版本以原子方式发布，发布后保持不变，由消费者在启动前下载。

前端和模型服务的代码包发布到工作负载的持久缓存，发布完成后才在服务上选择该版本。发布进程使用运行时镜像的用户身份，与提供推理服务的 Pod 分开运行。

## 引擎源码与编译扩展

显式关联的引擎源码与仓库固定的 vLLM Rust 依赖相互独立。Python 模块来自关联源码，并应用 Foretoken 补丁；兼容动态库和生成的依赖文件由运行时提供。删除的输入不再出现在后续代码包中，仅更新 Python 时保留已编译的扩展。

原生扩展使用所选运行时的 Python、PyTorch 和设备库，复用上游增量缓存。镜像构建打包准备好的源码并解析依赖，保持设备 ABI 兼容。沐曦原生扩展更新使用编译后的插件，而非预编译 kernel 包。

## 工作负载生效

CLI 在服务上选择源码版本，控制器负责前端滚动更新和模型 Pool/Group 替换。模型准备与推理使用同一选择，由镜像引导代码启用可执行文件、Python 适配代码和引擎代码包。声明的可执行文件缺失时，启动失败。

CLI 核对所选工作负载、实际启用的源码、路由状态和 Service 端点后报告成功。控制器负责请求准入、路由撤回和请求排空；前端对空路由快照的确认独立于服务就绪状态。

## 镜像更新与清理

数据面引导代码、依赖、镜像构建配置和 Helm 配置变化时，使用平台安装流程。运行时更新在可写存储不可用、或单节点存储卷等待首次放置时也使用镜像；首次存储放置由模型准备流程负责。源码安装成功后清除服务的源码选择和控制面的文件选择，使工作负载使用新镜像。

控制面清理保留 Helm 历史、工作负载模板、运行 Pod 和 VideoTask 计划引用的版本。运行时代码清理保留服务选择、模板，以及共享数据目录各命名空间内运行中或正在终止的消费者。两条路径都只删除本绑定不再使用的发布版本。

运行时编译卷跟随模型缓存的生命周期；Helm 管理控制面的文件服务和发布卷。源码卸载会删除托管编译缓存和工作站绑定，保留模型数据。vLLM-Omni 使用独立的[镜像构建配方](../custom-deployment_zh.md#vllm-omni-运行时)。
