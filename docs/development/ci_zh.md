# CI 规范

[English](ci.md) | 简体中文

CI 准备执行环境、调用仓库已有检查和选定的特征测试，并报告结果。例如，数据面 workflow 调用 `make verify-data-plane`，不另写 Rust 验证实现。

先运行[本地检查](testing_zh.md#运行相关检查)，再通过获准的运行验证改动后的 CI 编排。语法检查不能证明触发条件、runner 权限或产物传递可用，未执行部分据实说明。

## 新增自动化前取得认可

先阅读当前 workflow 及其调用的命令，明确要验证的基础检查、关键特征或发布产物，以及已有执行的缺口、自动化价值、时间和资源成本、失败负责人。优先调整已有任务。新增常驻任务、workflow、矩阵维度或定时运行前，取得维护者认可。新增功能、修复 bug、临时故障和一次性迁移不自动构成永久基础设施的理由。

保留测试、安排 CI 执行、设为合并必需检查，是三个独立决定。合并要求须明确取得对必要性、可靠性、成本、失败负责人和跳过行为的认可，不在添加任务时顺带扩大分支保护。

| 职责 | 范围 |
| --- | --- |
| 基础检查 | 对相关改动快速检查格式、静态分析、编译和生成产物一致性 |
| 关键特征 E2E | 按[测试规范](testing_zh.md)，使用实际依赖和硬件验证选定的产品特征 |
| 发布自动化 | 沿已有路径构建、验证并发布当前版本的产物 |
| 通知 | 报告 workflow 或仓库活动，不实现检查或控制产品行为 |

## 保留一条可复现的执行路径

Workflow 负责环境准备、命令调用、诊断和清理。断言与部署生命周期放在所属仓库验证入口，不堆入 YAML 长 shell 脚本。开发者具备文档说明的依赖后，应能在 CI 平台外执行同一操作。获准场景需要新入口时，放在特征的验证职责内，不另建 CI 实现。

复用准备和构建路径。验证同一组源码与依赖的兼容任务可共享产物，不必分别重建。缓存用于依赖和编译工作，不用于复用通过结果或旧二进制。

运行当前改动构建的包或镜像，确认正式安装、启动和选定特征使用该产物。直接执行源码不能验证 wheel 或镜像，手工修补运行中的容器不能验证分发镜像。在所属验证中检查资源语义字段，不计数渲染文本。编译、渲染和 dry-run 不是 E2E；缺少真实依赖或设备意味着未执行，不用 mock 或跳过结果代替通过。

## 选择触发条件、资源和权限

按受影响特征及依赖选择任务。路径过滤包含共享协议、依赖声明与锁文件、构建和部署配置及验证入口，不只看相邻源码。影响不确定时，选择范围更完整的相关已有任务，不静默漏过。

快速检查与昂贵的集群、GPU、多节点和性能运行分开。选择代表性组合，不穷举模型、硬件、拓扑和参数。按需执行足够时不安排定时运行；定时执行须对应具体缺口。验证设备属于执行条件，不是通用用户前提。

明确并发与超时，取消过时验证时保留清理；发布和共享环境操作采用符合自身职责的取消策略。

每次运行在成功、失败和取消后清理本次拥有的可变资源。共享 runner 不能修改其他运行的状态或删除其他工作负载。复用已有身份和生命周期机制，不另建内容哈希、冻结基线或资源管理框架。

只使用必要权限和凭据。不可信 PR 代码不能取得发布凭据，或无限制访问共享 GPU runner 和集群。选择可信执行上下文或隔离环境，不通过高权限事件绕过 fork 限制。

## 审查执行与维护成本

第一轮追踪正确性，从事件和变更选择检查环境准备、构建、产物传递、调用、报告和清理。在目标环境运行所属命令，查看输出和清理，并通过获准运行验证 CI 编排。

核对产物身份、真实依赖、事件可信程度、超时及失败和取消路径。检查过滤、跳过和取消后的合并必需检查状态，既不能虚报验证，也不能一直等待。

报告实际执行内容、源码或产物版本、必要环境条件和结果，区分产品失败、准备失败和未执行。保留有用命令输出和组件诊断，不包含凭据、敏感请求或私有基础设施信息。

不通过一律重试、无条件成功、吞掉退出码或空结果掩盖失败。定位偶发失败，修复期间明确停用或隔离不可靠检查，不将其报告为可信的通过。

第二轮独立检查必要性和简洁性。删除重复构建、复制的部署生命周期、workflow 中的业务断言、过时任务和无用矩阵组合。每项任务应有区别于已有检查的当前职责，优先用代表性特征执行代替扩大矩阵、新增调度层或门禁。保留发布与通知的独立职责，不因它们与测试共用目录就删除。
