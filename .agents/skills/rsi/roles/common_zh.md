# RSI 角色协作约定

[English](common.md) | 简体中文

亲自阅读适用的仓库规范、任务、角色说明、分配的源码和原始证据，使用当前运行环境提供的原生工具。缺少输入或授权时向主 Agent 询问，不自行替换任务或资源池。

主 Agent 负责整体方案、任务拆解、证据整合、反思、方向调整、资源与人员协调、验收和用户交付。具体研究、代码分析、实现、部署、测量和记录由团队分工完成，主 Agent 也可参与执行。参与其他成员负责的文件或资源前，先协调归属。遵守分配的范围、资源权限、剩余预算和暂停状态；以证据提出优先级或资源调整建议，不自行调派成员或扩大访问权限。

后续任务沿用角色上下文。通过原生消息直接与相关成员交流证据和问题，将记录修改建议直接发给指定作者。向主 Agent 报告结果、阻塞和需要其决策的变化。在分配的 worktree 中编辑和执行，从记录的位置读取候选证据。只写分配的文件或章节，保留其他作者的记录，链接原始证据而非复制报告。改动和证据保存后，请主 Agent 协调集成与 worktree 清理。区分假设、观察、执行者解释和有独立证据支持的结论。

若原生共享 Task 工具可用，且主 Agent 已授权自行认领，可以在授权范围和资源分配内认领已就绪、无人负责的工作，并告知主 Agent。否则直接请求任务，等待明确分配。不创建共享队列、注册表、定时器或反复查询状态的循环。探索始终围绕任务目标和分配的资源预算。

完成或遇到阻塞时，主动向主 Agent 交付结果或阻塞原因、证据路径、建议的下一步，并请求新任务。返回时将请求写入原生完成结果；需要在任务结束前处理的阻塞，通过直接消息报告。每次交接只发送一次，以以下请求结束：

> 请处理本次结果，并按 RSI 并行要求续派可独立推进的工作。请分配我的下一项任务，或明确让我等待、暂停或结束。

英文工作使用：

> Please process these results and assign follow-up work that can proceed independently, in line with the RSI task's parallelism requirements. Please assign my next task, or confirm that I should wait, pause, or finish.

交接后，只继续执行已获授权的认领任务或明确分配的任务。有界验证或审查在问题得到回答后结束；等待和已完成的成员不计入有效工作人数。后续任务复用已有上下文，重新阅读发生变化的输入。用户要求暂停或停止、分配范围完成或到达截止时间时，在职责边界内停止，报告进程和证据状态，不为维持人数而编造工作。
